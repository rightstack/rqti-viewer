rqti-viewer 0.4.6 — MathJax 중첩 재조판 재현

수업보드를 한 시간 넘게 열어 두면 크롬이 STATUS_STACK_OVERFLOW로 죽는 문제의 최소 재현 파일입니다. 각 파일을 브라우저에서 열면 결과가 화면에 바로 출력됩니다.

이 문제는 교사웹·학생웹 코드에서는 고칠 수 없습니다.

문제가 되는 MathJax 설정이 @rightstack/rqti-viewer 번들 내부에 하드코딩되어 있어 앱에서 덮어쓸 수 없습니다. 수정은 rqti-viewer 쪽 패치로만 가능합니다. 앱 개발자는 패치된 버전으로 올린 뒤 검증하는 역할입니다.

여는 방법

  1. 아래 표의 파일명을 클릭하거나, 파일을 브라우저로 끌어다 놓습니다.
  2. MathJax를 CDN에서 받으므로 인터넷 연결이 필요합니다.
  3. 2~3초 뒤 화면에 RESULT 블록이 나타납니다.
  4. depth(DOM 깊이)가 사이클마다 커지면 재현된 것이고, 고정이면 차단된 것입니다.

각 파일은 typesetClear() → typesetPromise()를 12회 반복합니다. 운영에서는 presence 수신 때문에 이 사이클이 5초마다 돌고, 1시간이면 약 720회가 됩니다.

04·05는 "이건 해봤는데 안 된다"는 기록입니다. 같은 시도를 반복하지 않도록 함께 넣었습니다.

무슨 일이 일어나는가

뷰어는 수식마다 <MathJax dynamic>(better-react-mathjax 3.0.3)을 쓰고, MathJaxContext에 src를 지정하지 않아 기본값 tex-mml-chtml.js가 로드됩니다. 이 번들에는 MathML 입력 처리기가 들어 있습니다.

dynamic 모드는 부모가 리렌더될 때마다 typesetClear() → typesetPromise()를 다시 돌립니다. 이때 MathJax가 이전 출력에 접근성용으로 심어 둔 <mjx-assistive-mml> 안의 MathML을 새로운 입력 수식으로 인식해서, 기존 출력 안에 새 출력을 중첩시킵니다. typesetClear()로는 이 노드가 지워지지 않습니다.

결과적으로 리렌더 1회당 DOM 깊이가 2씩 늘어납니다. 깊이가 수천 단이 되면 Blink의 레이아웃·스타일 계산(노드마다 재귀 호출)이 네이티브 스택을 넘겨 렌더러 프로세스가 종료됩니다. 같은 사이트의 탭들은 렌더러를 공유하므로 전부 함께 죽습니다.

권장 패치

02번 방식입니다. MathML 입력만 빠지고 뷰어는 TeX만 쓰므로 기능 손실이 없으며, 보조 MathML(스크린리더)도 그대로 유지됩니다.

rqti-viewer — MathJaxContext 설정
// MathJaxContext에 src를 명시한다 (현재는 미지정 → 기본값 tex-mml-chtml.js)
<MathJaxContext
  version={3}
  config={config}
+ src="https://cdn.jsdelivr.net/npm/mathjax@3.2.2/es5/tex-chtml.js"
>

추가로 검토할 것 — 내용이 바뀌지 않는데도 리렌더마다 전체를 다시 조판하는 구조 자체가 불필요한 부하입니다. 뷰어는 이미 key 교체로 문항을 갈아끼우므로, dynamic을 끄고 마운트 시 1회만 조판해도 동작에 지장이 없습니다.

패치 전까지 앱 레벨 우회책은 없으며, 임시 완화는 0.4.2로 롤백뿐입니다.
